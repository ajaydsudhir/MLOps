# Day 23: Search and Query MLflow Runs

## Task
A xFusionCorp Industries data scientist has accumulated ten runs in the `fraud-detection` MLflow experiment. Your task is to triage those runs via the **MLflow UI**: mark the single best-performing candidate as the shortlisted model, and flag every clearly under-performing run for removal.

1. The MLflow tracking server is already running on port `5000`, and the `fraud-detection` experiment has been pre-populated with ten runs. The runs can be viewed via the **MLflow UI** button → `fraud-detection` experiment.
2. Using the MLflow UI, complete the triage below. The end state is what is tested—the path taken through the UI is not.
- **Shortlist the best candidate.** Among all runs where `metrics.f1_score > 0.85`, the single run with the highest `f1_score` must carry a run-level tag: key `review-statu`s, value `shortlisted`.
- **Reject the under-performers.** Every run where `metrics.f1_score < 0.75` must carry a run-level tag: key `review-status`, value `rejected`.
3. The other runs (those in the 0.75 ≤ f1 ≤ 0.85 band, and the second-best shortlisting candidate) must carry no `review-status` tag at all.

## Solution
1. Open the MLflow UI and navigate to the `Evaluation runs` section of the `fraud-detection` experiment.
2. Use the search bar to filter runs with `metrics.f1_score > 0.85`. Among the filtered runs, identify the one with the highest `f1_score` and add a run-level tag: key `review-status`, value `shortlisted`.
3. Next, filter runs with `metrics.f1_score < 0.75`. For each of these runs, add a run-level tag: key `review-status`, value `rejected`.
4. Confirm that the runs in the 0.75 ≤ f1 ≤ 0.85 range have no `review-status` tag.

## Notes
- The MLflow UI supports a powerful search syntax for filtering runs based on metrics, parameters, and tags.
- Run-level tags can be added by clicking on the run in the UI, navigating to the "Tags" section, and adding a new tag with the specified key and value.
- https://mlflow.org/docs/latest/ml/search/search-runs/
